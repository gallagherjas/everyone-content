# 抖音指数采集

先按[账号操作](../account-profile/references/MULTI_ACCOUNT.md#账号操作)确认活动账号和 API 请求头。

## 配置采集

先读取该账号的授权状态、关键词和采集配置，按用户要求修改或补齐初始化缺项。

1. 在「设置 → 采集设置」点击「扫码连接抖音指数」，提示用户在独立的官方登录窗口扫码并完成页面验证。会话保存在本机私有目录，目录权限为 `0700`，文件权限为 `0600`。无需导出 Cookie 或复用已有浏览器资料。
2. 在「设置 → 关键词」至少启用一个采集词，再到「设置 → 采集设置」配置排除词和筛选参数。排除词可留空，采用默认规则也要点击「保存并重新筛选」。保存后重新读取配置核对。
3. 按用户选择配置定时采集，设置见[请求上限与定时](#请求上限与定时)。

## 执行采集

核对该账号的授权与有效关键词。在工作台可进入「采集 → 发现结果」，点击「手动采集」并查看进度和最近采集记录。

通过 API 执行时，启动前先读取已有采集记录，再按返回的 `run_id` 查询进度，直至当轮结束。读取新增记录和发现结果，按实际情况报告成功、失败、延后或无到期任务，并说明发现结果是否采齐。

### 命令行

把示例中的 `42` 换成目标账号编号。三条命令依次执行采集、将本轮限制为最多 3 次请求、只在本地规划任务。

```sh
npm run collect -- --account=42
npm run collect -- --account=42 --limit=3
npm run collection:plan -- --account=42
```

省略 `--account` 会选中所有活动账号。加上 `--scheduled` 时，按账号的定时开关进一步筛选。

### 私有文件导入

如已持有本人的 Cookie JSON 或 Playwright storageState，可登记已有的私有授权文件。Cookie JSON 使用 `cookie`，可选填 `userAgent`。将示例中的编号和路径换成实际值，文件权限设为 `0600`，凭据保存在私有目录。

```sh
npm run collection:plan -- --account=42 --auth="/你的私有目录/指数授权.json"
```

## 请求上限与定时

指数的每日请求额度由所有账号共享，默认每天 30 次，北京时间 08:00 重置。失败请求也计入额度。请求间隔至少 2 秒，每轮最多 10 次。

定时默认关闭。在「设置 → 采集设置」开启后，可填写 1–24 个北京时间时点，每轮设为 1–10 次请求。保持本地服务运行。重启或唤醒时只检查当天最近一个到期时点。

## 筛选规则

默认筛选条件为 30 天话题指数至少 10000、最多 3 个话题、视频至少 100 赞、最多 40 条视频和 5 个达人候选。话题上限最多可设为 5，点赞门槛最低为 100。

关键词视频和话题关联视频按作品合并。标题或标签命中排除词、点赞数未知的作品不入选。各查询的指数分别排序。仅有昵称的达人候选标为「主页身份待核实」。

## 核验与排查

- **缺少授权或登录失效。** 读取登录状态与采集记录，缺少授权时在目标账号的「采集设置」扫码连接，已知失效时重新登录。已保存会话但尚无成功请求，或因额度耗尽未能试采时，报告「待实采验证」。
- **共享采集资源占用。** 先查询当前采集进度。
- **数据尚未采齐。** 在「发现结果」查看待采集项。额度允许时再次点击「手动采集」，或等下一次定时任务。
- **采集成功但没有入选结果。** 分别说明访问结果和筛选结果。核对关键词、排除词和筛选门槛，在「最近采集记录」打开「查看记录」检查实际入库数据。
- **采集任务暂停。** 在「采集任务」查看原因。处理登录、限流或连接问题后，可用「恢复」解除暂停。
- **连接失败。** 检查本机能否访问抖音指数以及代理设置。程序对 `localhost`、`127.0.0.1` 和 `::1` 使用直连。

## 本地 API

| 请求 | 用途和参数 |
|---|---|
| `GET /api/index-auth` | 读取当前账号的登录状态。 |
| `POST /api/index-auth/start` 或 `POST /api/index-auth/cancel` | 打开或取消专用登录窗口。请求体留空。 |
| `GET /api/sources` | 从 `keywords` 读取本账号关键词。`ready` 表示启用，`paused` 表示暂停。旧版配置的 `config.index.tasks` 中的关键词也可参与采集。 |
| `POST /api/keywords` | 添加关键词，提交 `{"keyword":"要采集的词"}`。 |
| `PUT /api/sources/:id` 或 `DELETE /api/sources/:id` | 修改关键词状态或移出关键词。PUT 提交 `{"status":"ready"}` 或 `{"status":"paused"}`。 |
| `GET /api/collection/config` 或 `PUT /api/collection/config` | 从 GET 返回的 `config` 读取设置。排除词字段为 `config.index.discovery.excludeKeywords`。首次保存默认筛选规则时将 `config.index.discovery` 设为 `{}`，服务会补齐默认值。编辑 `config.index` 或 `config.schedules` 后，将修改后的完整对象放到 PUT 请求体同名顶层字段。 |
| `POST /api/run/collect` | 手动运行到期任务，请求体留空。响应包含轮次编号 `run_id`。 |
| `GET /api/collection` | 读取采集记录 `runs`、任务、额度及发现结果。 |
| `GET /api/collection/progress?run_id=<轮次编号>` | 读取指定轮次的进度和状态。`running` 为 `false` 时，`status` 区分完成 `done`、部分失败 `partial` 和失败 `failed`。省略编号时返回当前账号最近一轮。 |
| `GET /api/collection/records/:id` 或 `GET /api/collection/records/:id/raw` | 用采集记录编号读取本次入库数据或原始响应。 |
| `POST /api/collection/resume` | 解除本账号指数任务的暂停，提交 `{"provider":"index"}`。 |
