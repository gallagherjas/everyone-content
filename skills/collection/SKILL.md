# 抖音指数采集

先按[账号操作](../account-profile/references/MULTI_ACCOUNT.md#账号操作)确认活动账号和 API 请求头。

## 配置采集

先读取该账号的授权状态、关键词和采集配置，按用户要求修改或补齐初始化缺项。

1. 优先直接打开抖音创作者中心，提醒用户扫码。或者提醒用户在「采集 → 连接」点击「扫码连接抖音指数」，提示用户在独立的官方登录窗口扫码并完成页面验证。会话保存在本机私有目录，目录权限为 `0700`，文件权限为 `0600`。无需导出 Cookie 或复用已有浏览器资料。
2. 先根据用户画像，为其推荐5个采集关键词，并询问用户“是否要直接进行配置？有其他关键词也可以向我提供。”并提醒用户，可以在「采集 → 采集词」配置采集词和排除词，增删即时生效并按已有数据重新筛选。仍命中其他采集词的结果可以继续上榜。保存后重新读取配置核对。
3. 按用户选择配置定时采集，设置见[请求上限与定时](#请求上限与定时)。

多个工作台帐号使用同一个抖音帐号时，在「采集 → 连接」的抖音指数行选择「复用其他帐号」，选用已有可用会话。连接状态显示共用的工作台帐号，平台返回昵称或抖音号时也会一并显示。在任一共用帐号上重新登录会更新这份会话。采集设置和历史仍按工作台帐号保存。

## 博主追踪

用户想以博主为单位跟踪数据时，连接抖音指数后在「采集 → 博主」输入抖音昵称。每次昵称搜索消耗 1 次额度，匹配后开始追踪。每个博主每天固定消耗 1 次采集作品榜，可按博主开启日增曲线与资料页，各追加 1 次/天。开关、移出与添加都在「采集 → 博主」。「博主」页的作品默认按发布时间从新到旧展示，可切换为按点赞从高到低。

登记后可查看待解析、解析中、解析受阻、失败或延后的状态。服务会按额度和退避时间续跑待解析昵称与首轮作品采集。登录失效时重新连接，服务会继续处理已有登记。平台成功返回但找不到昵称时，可移出该条登记后添加正确昵称。

## 执行采集

核对该账号的授权与有效关键词。在「采集 → 总览」选择话题榜、视频榜、博主追踪或已连接的创作后台，点击对应行的「手动采集」。达人指数随视频榜更新。轮次进度显示在该行，采集明细见「采集 → 日志」。来源缺少可读授权、已知登录失效或暂停时，先按页面提示连接或恢复来源。

失败记录右侧的「重试」会重新执行该条任务及所需的数据日期查询。重试仍受来源状态、次数上限和请求间隔约束。

话题榜和视频榜共用抖音指数的话题有效日期查询，每次查询消耗一次指数额度。博主作品采集直接以北京时间当天为截止日。

在「采集 → 队列」统一查看本账号的任务状态及上次成功时间。本日已取得可用数据的任务显示「本日已采」。待执行表示任务已到可执行时间；实际运行还取决于采集范围和剩余额度。每轮明细见「采集 → 日志」。

通过 API 执行时，启动前先读取已有采集记录，再按返回的 `run_id` 查询进度，直至当轮结束。读取新增记录和发现结果，按实际情况报告成功、失败、延后或无到期任务，并说明发现结果是否采齐。

### 命令行

把示例中的 `42` 换成目标账号编号。三条命令依次执行采集、将本轮限制为最多 3 次请求、只在本地规划任务。

```sh
npm run collect -- --account=42
npm run collect -- --account=42 --limit=3
npm run collection:plan -- --account=42
```

省略 `--account` 会选中所有活动账号。加上 `--scheduled` 时，按账号的定时开关进一步筛选。加上 `--only` 只采对应范围，取值同本地 API 的 `only`，省略时采全部。

### 私有文件导入

如已持有本人的 Cookie JSON 或 Playwright storageState，可登记已有的私有授权文件。Cookie JSON 使用 `cookie`，可选填 `userAgent`。将示例中的编号和路径换成实际值，文件权限设为 `0600`，凭据保存在私有目录。

```sh
npm run collection:plan -- --account=42 --auth="/你的私有目录/指数授权.json"
```

## 请求上限与定时

采集日和每日额度每天北京时间 00:00 换日。指数的每日采集次数上限由所有账号共享，默认每天 30 次。失败请求也计入次数。请求间隔至少 2 秒，每轮最多 10 次。

创作后台快照各平台独立限额：每天 10 次、请求间隔 1 小时、每轮 1 次。同一采集日手动再次采集同一后台时复用快照。未到请求间隔时任务标记延后并释放采集资源，到点后由下一次采集补上。

定时默认关闭，预填北京时间 00:00。在「采集 → 定时」为话题榜、视频榜、博主追踪和各创作后台分别设置 1–24 个北京时间时点，每轮设为 1–10 次请求。已启用的旧版合并定时也可在此管理。保持本地服务运行。重启或唤醒时，每个范围只检查当天最近一个到期时点。

## 核验与排查

- **缺少授权或登录失效。** 读取登录状态与采集记录，缺少授权时在目标账号的「采集 → 连接」扫码连接，已知失效时重新登录。已保存会话但尚无成功请求，或因每日次数用尽未能试采时，报告「待实采验证」。
- **共享采集资源占用。** 先查询当前采集进度。
- **数据尚未采齐。** 在「指数」查看待采集词。次数允许时在「采集 → 总览」再次采集对应范围，或等下一次定时采集。
- **采集成功但榜单为空。** 分别说明访问结果和排除结果。核对关键词与排除词，在「采集 → 日志」打开「查看记录」检查实际入库数据。
- **采集暂停。** 在「采集 → 日志」查看失败原因。授权异常时重新连接来源。处理限流或权限问题后，在「采集 → 总览」点击「恢复采集」。
- **任务连续失败停用。** 同一任务连续失败 3 次即停止自动重试。处理失败原因后可手动重试。
- **连接失败。** 检查本机能否访问抖音指数以及代理设置。程序对 `localhost`、`127.0.0.1` 和 `::1` 使用直连。

## 本地 API

| 请求 | 用途和参数 |
|---|---|
| `GET /api/auth/index` | 读取抖音指数登录状态、平台帐号 `account_name`、共用会话的工作台帐号 `session_accounts` 和可选来源 `reuse_accounts`。 |
| `POST /api/auth/index/start` 或 `POST /api/auth/index/cancel` | 打开或取消专用登录窗口。请求体留空。 |
| `POST /api/auth/index/reuse` | 提交 `{"source_account_id":42}`，将当前帐号绑定到所选工作台帐号的抖音指数会话。 |
| `GET /api/sources` | 从 `keywords` 读取本账号关键词。旧版配置的 `config.index.tasks` 中的关键词也可参与采集。 |
| `POST /api/keywords` | 添加关键词，提交 `{"keyword":"要采集的词"}`。 |
| `DELETE /api/sources/:id` | 移出关键词，同时清除旧版指数配置中该词对应的任务。 |
| `GET /api/bloggers` | 读取博主追踪列表，含昵称解析状态 `searchState`、原因 `error`、可自动重试的时间 `nextRetryAt`，以及已匹配博主的概览。 |
| `POST /api/bloggers` | 添加博主，提交 `{"keyword":"抖音昵称"}`；解析与首轮作品采集自动进行。 |
| `PUT /api/bloggers/:id` 或 `DELETE /api/bloggers/:id` | 调整博主采集项或移出。PUT 提交 `{"status":"ready"|"paused"}`、`{"core":true}` 或 `{"info":true}`。 |
| `GET /api/collection/config` 或 `PUT /api/collection/config` | 从 GET 返回的 `config` 读取设置。排除词字段为 `config.index.discovery.excludeKeywords`。首次保存时将 `config.index.discovery` 设为 `{}`，服务会补齐默认值。编辑 `config.index` 或 `config.schedules` 后，将修改后的完整对象放到 PUT 请求体同名顶层字段。 |
| `POST /api/run/collect` | 手动运行到期任务，请求体留空采所有可用来源，或提交 `{"only":"<范围>"}`。`topic_rank` 采话题榜，`video_rank` 采视频榜，`author` 采博主追踪，`douyin`/`xhs`/`bili` 采对应平台快照。`index` 采整个抖音指数，旧版 `topic` 仍可合并采话题榜和视频榜。响应包含 `run_id`。 |
| `GET /api/collection` | 读取采集记录 `runs`、任务 `tasks` 及其 `status`、队列计数 `queue`、每日采集次数上限及发现结果。`blockers` 返回各来源的阻塞原因，可用来源对应 `null`。 |
| `GET /api/collection/progress?run_id=<轮次编号>` | 读取指定轮次的进度和状态。结束后的 `status` 为完成 `done`、部分失败 `partial`、失败 `failed`、已有结果且部分延后 `done_with_deferred`、延后 `deferred`、复用缓存 `cached` 或无可执行任务 `empty`。省略编号时返回当前账号最近一轮。 |
| `GET /api/collection/records/:id` 或 `GET /api/collection/records/:id/raw` | 用采集记录编号读取本次入库数据或原始响应。 |
| `POST /api/collection/records/:id/retry` | 重试当前账号的一条失败记录，响应包含 `run_id`。 |
| `POST /api/collection/resume` | 恢复本账号已连接来源的采集，提交 `{"provider":"index"}` 或对应平台标识。 |
