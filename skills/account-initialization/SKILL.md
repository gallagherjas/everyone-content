# 账号初始化

## 进入条件

日常入口先看项目`AGENTS.md`顶部的一句话状态。当前账号已完成时直接继续原任务，不读取本Skill。只有当前账号未完成、状态缺失，或用户明确要求初始化、补全画像时才进入。状态不清楚时用`GET /api/initialization`确认服务及本账号；服务未就绪时按[安装说明](../../README.md)处理，不把连接故障当作画像缺失。

## 完整填写画像

读取本账号的生效画像及已有草稿，再依据[画像框架](../../prompts/account-profile.md)，逐项收齐以下七部分：

1. 账号定位。
2. 身份与人设。
3. 目标人群。
4. 目标与转化。
5. 内容策略。
6. 内容形式与制作条件。
7. 品牌与边界。

根据每一节的填写提示，把所需信息问清楚，不预设问题数量或为了缩短流程略过章节。用户已提供的信息直接归入对应章节，缺失、含糊或互相矛盾的信息继续澄清，不形式化重复提问。

不虚构用户定位、人设、经历、目标或边界。账号定位和目标人群须给出具体信息；其他部分确实不适用时，由用户明确说明并记录，不能由Agent默认填「无」或「不适用」来凑齐。暂未确定的项目可以保存草稿，但初始化继续保持未完成。

## 保存与完成

将完整画像呈现给用户核对，按实际保存授权使用现有机制：`GET /api/strategy`取得当前版本，`PUT /api/strategy/draft`提交`docs`及`base_sha`，`POST /api/strategy/publish`提交`base_sha`及`note`。页面对应「设置 → 账号画像 → 保存并生效」。账号规则与画像版本说明见[账号说明](../../docs/MULTI_ACCOUNT.md)。

完成以系统返回的`initialized=true`为准。程序检查全部七个章节是否填写，并把结果绑定当前生效版本；草稿、占位提示、聊天中的口头确认不改变该状态。缺项时根据`missing_sections`继续补全，不直接写完成标记。

初始化完成后，必须将状态用一句话写进项目根目录`AGENTS.md`的`everyone-content:initialization`固定标记区，注明账号编号及生效画像SHA。服务保存生效时自动同步此句，Agent核对`instructions_synced`和文件结果；未同步时先完成同步，不能声称已写好。只更新该区域，保留其他指令，不写用户正文、原文、账号自由文本或登录凭据。示例：「初始化状态：账号 1 已完成七部分画像（strategy_sha=当前生效SHA）。」后续Agent从这一句判断，不再加载初始化文档。

完成后继续用户原本要求的[选题评估](../topic-review/SKILL.md)或[个人写作](../personal-writing/SKILL.md)。没有后续请求时说明可用能力即可，不自行出题、写稿、采集或发布。

## 按需连接指数与写作资料

画像初始化不要求同时登录指数或提供写作样本。用户需要采集时，在「设置 → 采集设置 → 连接抖音指数」打开专用登录窗口，扫码并完成页面验证，会话自动保存并绑定当前账号；不让用户手工寻找Cookie，也不读取既有浏览器资料。采集设置见[采集说明](../../docs/COLLECTION.md)。

用户需要写作时，再收集本人的实质写作偏好或原文，任一种即可。模板见[偏好](../personal-writing/assets/writing-preferences.md)及[原文](../personal-writing/assets/user-original.md)。只要求初始化或评估时不生成文案。
