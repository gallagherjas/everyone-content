# 账号初始化

## 首次使用入口

首次响应用户使用本项目的请求时，先执行本节，不等待用户说「初始化」。明确的代码维护、测试、Git操作、架构与需求讨论除外。仅安装项目或注册Skill不会自行发起对话。

1. 先读 [安装与使用说明](../../README.md)。确认项目处于Git仓库、Node.js版本满足要求；请求本地`GET /api/health`，只有返回`app: everyone-content`才读取该服务的账号。默认端口为8788，按本项目实际端口连接；身份不符时先解决端口或项目连接问题，不读取其他服务的账号。服务未启动时先帮助启动或说明具体缺项，不把连接故障当作画像为空。工作台是本地页面，Agent在打开该仓库的对话中工作，不能让用户寻找不存在的工作台聊天入口。
2. 通过 `GET /api/accounts` 了解现有账号。新安装会有空白「默认账号」，它是本地内容运营空间，不是已登录的抖音账号；即使已有画像SHA也可能只是空白模板。先确认用户要使用、改名或新建哪个空间，不套用原作者、默认编号或其他账号的定位与授权。
3. 对未初始化账号，先用少量问题了解「账号怎么称呼、主要做什么、给谁看」，已有答案不重复问。之后按需补充目标、资源和边界，不能一次要求填完整份画像。用户尚未确定方向时帮助澄清，不代其决定，也不先生成选题或文案。
4. 将用户确认的定位和目标人群整理到画像；获得保存授权后，复用现有画像机制保存并生效，再读取生效版本核对。`GET /api/strategy`取得当前`sha`；`PUT /api/strategy/draft`提交`docs`和`base_sha`；`POST /api/strategy/publish`提交`base_sha`和改动说明`note`。只保存在聊天或草稿中，不能宣布初始化完成；页面操作对应「设置 → 账号画像 → 保存并生效」。
5. 基础画像生效后即可评估用户自己的选题。需要采集时再准备该账号的关键词、博主、来源依赖和授权；写作资料可后补。说明当前可用的能力和下一步，只继续用户已经请求的任务。

## 评估与写作的前置检查

此检查是后续评估、写稿和改稿的必经步骤，不要求每次完整走初始化问答：

1. 确认本次 `account_id`；不明确时询问，不根据默认账号或另一账号的信息代选。通过带 `x-everyone-content-account` 的 `GET /api/context` 核对归属与生效画像版本，读取其 `account-profile.md`。
2. 检查画像中的账号定位和目标人群是否有用户实际填写的信息。只有标题、填写提示或未生效草稿不能当作已完成；缺项时保留原请求，按下面的用法只引导补齐这些信息。用户回复后在同一会话继续，不要求重新提交选题或写作请求。
3. 两项齐全即可继续原请求，无需另存初始化完成标记，也不补问与本次任务无关的字段。采集配置、指数授权、写作资料各按实际用途准备，不把所有可选资料设为通行条件；个人写作的资料准入仍由写作Skill检查。

无法读取当前账号或生效画像时说明核对受阻，不假定已初始化，也不因连接故障让用户重填。代码维护、测试、Git操作、架构与需求讨论不执行此检查。

## 用法

先读 [账号说明](../../docs/MULTI_ACCOUNT.md) 和 [采集说明](../../docs/COLLECTION.md)，了解当前账号、画像草稿及采集设置，已明确的信息不重复询问。新账号尚未创建时先帮助用户确定归属；创建后取得 `account_id`，后续API请求使用对应的 `x-everyone-content-account`。

围绕用户实际要做的账号补齐以下信息，可分轮询问，不要求一次填完：

- **账号画像**：依据 [现有空白框架](../../prompts/account-profile.md)，了解定位、身份、目标人群、目标、内容方向、制作条件和边界。仅整理用户已确认的信息，不虚构人设或替其决定方向；尚未确定的字段留空。
- **采集设置**：唯一来源为抖音指数。根据当前账号确认的方向，整理关键词、参考博主和排除词，区分建议与已确认配置，不套用其他账号的词或授权。参考博主只用于整理指数收录作品，不单独获取新作。引导用户通过私有文件登记本人指数授权，不索取或回显凭据；说明请求上限和定时需本地服务在线。保存配置不等于已请求数据，只有用户要求采集时才启动。
- **写作资料，可选**：说明只有用户提供本人的实质写作偏好或原文后才协助写作；可使用 [偏好模板](../personal-writing/assets/writing-preferences.md) 和 [原文模板](../personal-writing/assets/user-original.md)。不提供资料仍可完成初始化、查看采集结果并评估自己的选题。

返回已明确的画像和采集配置，以及尚待补充的信息。用户要求保存时复用现有设置和画像草稿机制；草稿、生效画像和建议须区分。画像发布、启用定时或发起采集按用户实际授权处理，初始化本身不启动采集或自动创作。个人写作资料当前没有登记接口，只交付整理结果，不宣称已持久化。

因评估或写作请求进入时，完成必要补全后读取相应Skill，继续用户原本的请求。用户只要求初始化时，说明后续使用方式即可：自行浏览和选择内容，再向 [选题评估](../topic-review/SKILL.md) 提供**标题、目标群体、主要价值（一句话）**；提供个人写作资料后，可按需使用 [个人写作](../personal-writing/SKILL.md)。不自行开始评估、写作或接入事件路由。
