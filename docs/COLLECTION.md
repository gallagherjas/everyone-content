# 抖音指数采集

采集使用抖音指数官方只读HTTP接口，取得近30天话题、关键词视频、入选话题关联视频及点赞、评论达人榜。所有配置与结果归属于明确账号，不自动选题或写稿。

## 首次配置

1. 启动工作台，确认当前账号，在「设置 → 博主与关键词」添加关键词。
2. 准备本人登录授权文件，存放在仓库外的私有目录。支持Cookie JSON或本人提供的storageState，文件权限须为0600。Cookie JSON的`cookie`字段为登录会话字符串，可附`userAgent`；项目不会读取或导出浏览器凭据。
3. 为当前账号登记文件：

```sh
chmod 600 /你的私有目录/指数授权.json
npm run collection:plan -- --account=1 --auth=/你的私有目录/指数授权.json
```

替换示例中的编号与路径。登记成功后指数启用；未授权账号不排指数任务。更新授权会解除当前账号的登录暂停并唤醒任务。授权值不写入数据库、参数日志或前端，数据库只保存文件引用。

4. 在「设置 → 采集设置」维护指数门槛、排除词及保留数量；点击「保存并重新筛选」只重算已有资料，不请求新数据。
5. 在「采集 → 发现结果」点击「手动采集」，或运行：

```sh
npm run collect -- --account=1
npm run collect -- --account=1 --limit=3
npm run collection:plan -- --account=1
```

`--account`选定账号，未指定时处理全部启用账号。`--limit`限制单轮请求数，`--plan`只规划本地任务。`--only=index`可显式指定来源。

## 筛选与数据

账号规则为空时，不推断采集方向，也没有预设行业关键词、博主或排除词。工程初值为30天话题指数10000、最多3个话题，最多可设5个；视频至少100赞，最多40条；达人候选最多5个。这些值可以调整，点赞底线不低于100。

话题先过门槛再按同一30天窗口排序。关键词与话题关联视频按作品ID合并，任一来源命中排除词则排除，点赞未知也不入选。不同查询的指数分别排序。关键词查询及入选话题关联采齐后才展示完整批次，避免用不完整数据得出结论。

来源有效日期更新后，过期查询立即到期，页面列出尚待补齐的话题、视频或关联查询。数据未齐、筛选后无结果和缺少授权是不同状态。

原始响应及解析缓存压缩保存在`runtime/collection/objects/`，数据库登记来源、窗口、观察时间及SHA256。未知指标保留null，话题阅读或播放统计不当作单视频播放量。昵称不作为平台身份合并依据。

参考博主只筛出本账号已收录且身份对应的作品，保存关注关系不请求网络。已发布作品仅在被本账号指数收录时追加指标，不提供独立互动轮询。

## 请求上限与定时

指数默认每天30次请求、最小间隔2秒、每轮最多10次，跨账号共享；失败请求也计数。每日额度在北京时间08:00重置。额度用于限制请求，不承诺来源可用性。

在「设置 → 采集设置」可开启定时，设置1–24个每日北京时间和每轮1–10次请求。开关默认关闭，关闭后仍可手动采集。需要保持本地服务运行；重启或唤醒只补当天最近一次，已触发时间点不重复。

任务使用租约、全局互斥、请求预算及有限退避。登录失效或限流暂停对应账号授权范围；协议异常停用对应接口；普通连接失败与配置问题分别显示。

## 本地API

`GET /api/health`返回服务名称，用于确认连接的是`everyone-content`，不需要账号。其他账号请求须带`x-everyone-content-account`：

| API | 用途 |
|---|---|
| GET `/api/context` | 当前账号及生效画像版本 |
| GET `/api/collection` | 任务、记录、额度及发现结果 |
| GET / PUT `/api/collection/config` | 读取配置、保存规则并重筛 |
| GET `/api/collection/records/:id`及`/raw` | 本账号解析或原始证据 |
| POST `/api/collection/resume` | 恢复本账号指数任务 |
| POST `/api/run/collect` | 手动运行到期任务 |

页面读取不隐式请求指数。外网连接需要可用网络和必要的代理；程序绕过localhost、127.0.0.1和::1。
