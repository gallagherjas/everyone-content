# everyone-content

## 它解决什么问题

做多账号内容的人通常面对三件散落的事：选题靠刷推荐流碰运气、账号定位和目标人群停留在脑子里、选题依据和数据对不上号。everyone-content 把它们收进一个本地系统：

- **采集有事实**：按账号配置关键词和筛选规则，从抖音指数取得话题、关键词视频与达人榜，以真实数据驱动选题，避免选题全靠猜、灵感全靠想。
- **决策有画像**：每个账号维护七部分画像（定位、人设、人群、转化、策略、形式、边界），评估选题时逐项对照，让选题更符合帐号定位与目标。

## 工作原理

这个项目由两部分组成：
**本地工作台**负责配置、采集和数据展示；
**Agent对话**负责画像和选题评估。

两者通过本地状态衔接：

```text
账号关键词、指数授权与筛选规则
  → planner：生成到期任务
  → runner：租约、限速、预算与请求
  → 原始响应、解析缓存、作品、作者、话题及指标观测
  → SQLite → 工作台
```

关键设计：

- **SQLite是唯一业务事实来源**。账号、订阅、授权、筛选规则和结果按`account_id`隔离，API逐请求核对归属。
- **画像用Git引用版本化**（`refs/everyone-content/profiles/<account_id>`），保存生效不切分支、不动暂存区，恢复版本生成新提交。
- **采集是确定性程序**，Agent不另写采集脚本；预算、去重、写库由planner/runner/store执行。
- **未知即null**。来源有效日期、统计窗口和观察时间分别保存。

## 快速开始

需要 **Node.js 24+**、**Git** 和一个能读取项目指令与本地Skill的Agent（Codex、Claude Code 等）。当前支持 macOS / Linux；指数扫码登录需要本机图形桌面。

```sh
git clone <仓库地址>
cd everyone-content
npm ci
npm --prefix frontend ci
npm run build:web
npm run web
```

打开 http://127.0.0.1:8788 。首次启动自动创建空白「默认账号」；订阅、授权、画像内容、采集结果和发布记录均为空。端口被占用时用`WEB_PORT=8789 npm run web`。

然后在Agent对话中说：

> 我第一次使用，带我设置一下

Agent会引导完成账号画像的七个部分，之后进入日常使用。

## 核心流程

1. **初始化账号**：完成帐户画像初始配置，保存生效后才能进入选题评估。也可在「设置 → 账号画像」操作。
2. **连接抖音指数**：「设置 → 采集设置 → 扫码连接抖音指数」。项目打开独立的官方登录窗口，扫码后登录会话私密保存于本机（目录0700、文件0600），不读取已有浏览器资料，无需手工导出Cookie。
3. **配置采集**：在「设置 → 关键词」添加关键词，再到「设置 → 采集设置」中配置采集参数，调整筛选规则，到「采集 → 发现结果」手动采集或配置每日北京时间定时。每日请求上限各账号共享、每轮最多10次。
4. **自行选题**：在「采集 → 入选视频」浏览结果，打开原平台观看后自行决定选题——系统不自动选题。
5. **Agent评估**：在对话中提交**标题、目标群体、主要价值（一句话）**，检查账号匹配、信息一致性和表达是否具体，可附参考作品。

「已发布」登记实际发布链接；作品被指数收录后展示来源指标，未收录保持未知。

## 多账号

账号是独立的本地内容运营空间，不等于抖音登录；首次启动自动创建空白「默认账号」。关键词、指数授权、筛选规则、画像和采集结果按账号分别维护，新账号从空白开始，不继承其他账号的资料。授权范围为`account:<编号>`，同词查询不借用其他账号的授权或结果。归档保留历史并停止写入与定时采集，恢复后继续使用。

详见[账号与画像](docs/MULTI_ACCOUNT.md)。

## 隐私与数据边界

- 所有数据保存在本机：SQLite数据库、运行资料、画像Git仓库，不连接任何第三方服务。
- `.env`、登录会话与授权文件属于密钥材料，权限0600，不提交Git、不回显到前端。
- 评估在对话中交付，工作台没有登记入口。
- 界面时间按北京时间解释，数据库时间使用UTC。

**使用边界**：本项目仅用于数据收集和灵感获取，拒绝抄袭、模仿行为。采集到的话题、视频与达人数据只作为选题的事实参考，创作请保持独立与原创。

**免责声明**：本项目通过官方登录窗口连接抖音指数，仅供个人对自有账号的内容研究使用。使用者应自行遵守平台服务条款与当地法律；内置的每日限额和限速应保持启用。作者不对使用方式承担责任。
